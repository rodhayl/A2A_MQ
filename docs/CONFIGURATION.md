# Configuration reference

This document is the maintained configuration reference for A2A-MQ. It covers the
supported local launchers and the deployable production role factories.

## Configuration model

A2A-MQ deliberately has two configuration styles:

1. **Local profiles** are generated by `a2amq-local prepare` or
   `a2amq-local-workflow prepare`. Generated profile files are not intended to be
   hand-edited.
2. **Distributed/production roles** are configured with environment variables and
   operator-managed secret references.

There is no second YAML configuration layer.

## Local-lite

Create a profile with:

```bash
a2amq-local prepare <profile-directory> [options]
```

Supported options:

| Option | Default | Meaning |
| --- | --- | --- |
| `--tenant` | `demo` | tenant token used in routes/storage |
| `--source` | `local-worker` | local agent/source identity |
| `--public-url` | `http://127.0.0.1:18000` | fixed loopback A2A origin |
| `--mcp` | disabled | also generate the local MCP client token |

The built-in launcher intentionally uses fixed loopback ports:

| Service | Port |
| --- | ---: |
| A2A-MQ HTTP | 18000 |
| Dapr HTTP | 3500 |
| Dapr gRPC | 50001 |
| Dapr internal gRPC | 50002 |
| NATS | 4222 |

Run the non-mutating preflight before startup:

```bash
a2amq-local doctor <profile-directory>
```

The launcher owns its Local-lite concurrency/storage defaults. They are not a public
per-profile tuning surface in v0.1.0.

## Local Workflow

The Workflow profile accepts the same `prepare` options:

```bash
a2amq-local-workflow prepare <profile-directory> [options]
a2amq-local-workflow doctor <profile-directory>
```

It adds native Placement and Scheduler ports controlled by the launcher. Do not
convert a Local-lite profile into a Workflow profile by editing `profile.json`;
prepare a new profile with the matching launcher.

## Generated local files

Important generated files include:

| File | Purpose |
| --- | --- |
| `profile.json` | generated local profile metadata |
| `app-api-token` | Dapr-to-app authentication secret |
| `dapr-api-token` | app-to-Dapr authentication secret |
| `nats-token` | local broker credential |
| `jwt-private.pem` | local-only signing key |
| `jwt-keys.json` | local JWT verification key map |
| `client.jwt` | A2A owner client token |
| `client-mcp.jwt` | MCP client token when `--mcp` is enabled |
| `state/` | local application/Workflow state |
| `nats/` | JetStream file state |

Generated local profiles contain secrets and must stay owner-private.

## Distributed/production roles

The production factories are:

- `a2a_mq.production_env:create_api_from_env`
- `a2a_mq.production_env:create_worker_from_env`
- `a2a_mq.production_env:create_dlq_from_env`

### Common variables

| Variable | Roles | Required | Default | Secret | Meaning |
| --- | --- | ---: | --- | ---: | --- |
| `A2A_TENANT` | API/worker/DLQ | no | `demo` | no | tenant namespace |
| `A2A_PUBSUB_COMPONENT` | API/worker/DLQ | no | `bus` | no | Dapr Pub/Sub component |
| `DAPR_HTTP_ENDPOINT` | API/worker/DLQ | no | `http://127.0.0.1:3500` | no | colocated Dapr HTTP endpoint |
| `DAPR_API_TOKEN` | API/worker/DLQ | one token source required | — | yes | direct Dapr API token |
| `DAPR_API_TOKEN_FILE` | API/worker/DLQ | one token source required | — | yes | file containing Dapr API token |
| `A2A_SQLITE_PATH` | API/worker/DLQ | exactly one storage backend | — | no | single-host SQLite path |
| `A2A_POSTGRES_DSN` | API/worker/DLQ | exactly one storage backend | — | yes | direct PostgreSQL DSN |
| `A2A_POSTGRES_DSN_FILE` | API/worker/DLQ | exactly one storage backend | — | yes | file containing PostgreSQL DSN |
| `A2A_POSTGRES_ALLOW_INSECURE` | API/worker/DLQ | no | `false` | no | explicitly allow non-verified PostgreSQL mode |

Exactly one application storage backend is allowed: SQLite **or** PostgreSQL.

`A2A_POSTGRES_DSN` and `A2A_POSTGRES_DSN_FILE` are mutually exclusive.
`DAPR_API_TOKEN` and `DAPR_API_TOKEN_FILE` are mutually exclusive.

Production deployments should normally use PostgreSQL. SQLite remains a single-host
backend.

### API role

| Variable | Required | Default | Secret | Meaning |
| --- | ---: | --- | ---: | --- |
| `A2A_CONSUMER` | no | `workflow-worker` | no | task/worker logical consumer |
| `A2A_DLQ_CONSUMER` | no | `operations` | no | DLQ logical consumer |
| `A2A_PUBLIC_URL` | yes | — | no | HTTPS public A2A origin |
| `A2A_MCP_RESOURCE_URL` | no | `<A2A_PUBLIC_URL>/mcp` | no | HTTPS MCP resource URL |
| `A2A_JWT_ISSUER` | yes | — | no | accepted HTTPS JWT issuer |
| `A2A_JWT_KID` | yes | — | no | configured JWT verification key ID |
| `A2A_JWT_PUBLIC_KEY_FILE` | yes | — | no | PEM public verification key |
| `A2A_BACKUP_DIR` | no | — | no | optional operator backup destination |

The API role reads only a public JWT key. Do not mount the issuer's private signing
key into the API pod.

### Worker role

| Variable | Required | Default | Secret | Meaning |
| --- | ---: | --- | ---: | --- |
| `A2A_CONSUMER` | no | `workflow-worker` | no | shared worker consumer |
| `A2A_SOURCE` | no | `workflow-worker` | no | task source/worker identity |
| `DAPR_GRPC_PORT` | no | `50001` | no | colocated Dapr Workflow gRPC port |
| `DAPR_GRPC_ENDPOINT` | rejected | — | no | remote gRPC endpoint is intentionally not supported |
| `APP_API_TOKEN` | one token source required | — | yes | direct Dapr-to-app token |
| `APP_API_TOKEN_FILE` | one token source required | — | yes | file containing Dapr-to-app token |

The worker requires colocated Dapr. A remote `DAPR_GRPC_ENDPOINT` fails closed.

### DLQ role

| Variable | Required | Default | Secret | Meaning |
| --- | ---: | --- | ---: | --- |
| `A2A_DLQ_CONSUMER` | no | `operations` | no | DLQ logical consumer |
| `APP_API_TOKEN` | one token source required | — | yes | direct Dapr-to-app token |
| `APP_API_TOKEN_FILE` | one token source required | — | yes | file containing Dapr-to-app token |

## Boolean values

Production boolean configuration is explicit and case-sensitive. Use:

```text
true
false
```

Values such as `1`, `yes` or `TRUE` are rejected.

## Secret source rules

For secret pairs such as:

```text
DAPR_API_TOKEN / DAPR_API_TOKEN_FILE
APP_API_TOKEN / APP_API_TOKEN_FILE
A2A_POSTGRES_DSN / A2A_POSTGRES_DSN_FILE
```

configure exactly one source. Supplying both fails with
`AMBIGUOUS_SECRET_CONFIG`.

The Kubernetes renderer uses Secret-backed environment references for the deployment
it generates. File variants remain useful for other operators/runtimes.

## Production renderer

The Kubernetes renderer translates its CLI inputs plus broker profiles into
application/Dapr manifests. It does not replace the environment-variable contracts
above; see [DEPLOYMENT.md](DEPLOYMENT.md).

## Diagnostics

For local configuration problems use:

```bash
a2amq-local doctor [profile]
a2amq-local-workflow doctor [profile]
```

For error-specific recovery steps see
[TROUBLESHOOTING.md](TROUBLESHOOTING.md).
